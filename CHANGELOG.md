# Changelog

## 0.8.0 — 2026-10-09
- **New node: WReso**, the resolution written large on the node, and nothing else. Plug a picture, or two INT cables (`width`, `height`: a resolution node, a WInt🌱, a Primitive), and read `1024 × 1024` at a glance; the same two numbers go out as INT. As small as a node gets: three sockets, two pins, the line. The line follows the graph as you wire (a picture shown up the cable, the widget at the far end of a cable through Reroute and Set / Get, a menu that reads `1024 x 1024` split in two, Comfy's Resolution Selector summed the way the backend does); what the graph cannot tell reads `?` until the run, then the line shows what the node used. It runs with nothing on its outputs, like a Preview. The same line on the classic canvas and under Nodes 2.0.
- WCheckpoint and WLoRA: the **`selection`** drop-down of WSampler / WScheduler, under `folder`. It reads `all · 12`, the menu as `folder` leaves it; open it, tick the names you want, drag them by the handle `≡` into order, close it and it reads `custom · 3`: from then on those names, in that order, are the menu of the name, and the walk of `increment` / `decrement` / `randomize` and the `carry` cable only meet them. The ticks follow the folder: a tick on a name outside the folder of now waits, and counts again when that folder comes back. `selection` is an optional input of the node, declared after the boxes of before: a saved workflow and an API prompt are valid as they are. One drop-down for the four nodes (`web/wxSelection.js`), in the slot of an ordinary widget: even with `folder` above and the name below.
- WInt🌱: **`selection`** under `value`, for seeds that are not one after the other. The row reads `free`; open it, type a seed and press Enter (or several at once, as the box shows: `1, 3, 6, 90, 1234`), drag them by the handle `≡` into order, ✕ takes one out, `sort`, `clear`; the row reads `custom · 4`. With seeds in it the walk is a wheel over them, in that order: `increment` the next, `decrement` the one before, `randomize` any of them, round at the ends, a beat down the `carry` cable at every round; `step` and `until` do nothing and are greyed out; the label reads `next/run · 4 picked ↻`. `value` is always one of them: a value outside the list goes to the first seed at once, so the first run queued is the first seed picked, not a stray one (the arrows of `value` go to the next / the one before in the list). `selection` is an optional input of the node, declared after the boxes of before: a saved workflow and an API prompt are valid as they are. WFloat does not have it.
- WInt🌱: **drop a PNG saved by ComfyUI on the node** and the seed that made it joins the list (read from the prompt inside the file: this node's value, else the first WInt🌱, else the first `seed` found). A seed found a week later in the output folder, back in the wheel with one gesture; the drop never opens the file as a workflow.
- **`⟲` and `▶ n` on the `carry` row** of every node that walks, alone or in a chain. `⟲` puts every wheel of the chain back to its first place (the first seed picked, the start of the wheel to `until`, the first name of the selection or the folder, the first slot): a grid interrupted half way, or a new one from the start, with nothing to set by hand. `▶ 12` does the same and then queues the runs of the whole grid, 12 = the sizes of the chain multiplied, or the node's own size when it is alone (the seeds picked, the wheel to `until`, the folder or the selection, the slots in use). A free walk by `step` has no size: then only `⟲`. The chips show only when something walks. `▶` writes the number in the **batch box next to Run** too (up to the limit in the settings): the next Run queues the grid again, with nothing to type.
- WSwitch: **every slot is a box** around its rows, the one that is on in blue, so the slots read apart at a glance; every pill at the same place, and after it a pencil **`✎`** and a handle **`≡`**. **The slots move**: drag one by its handle and drop it on another (it lights up), it takes that place and the ones between move up or down; cables, pill and name go with the slot, nothing to unplug (the sockets move with their cables, as in 0.7.0), and `index` counts the new order. **The slots have names**: click the pencil (or double-click the pill) and type one; a slot fed by a checkpoint, LoRA or UNet loader gets the bare file name by itself. The row reads `0 · krea`, and in WSave Image `{#id}` of a WSwitch is the name of the slot that is on (its number from 0 when it has none): the short name of the model in the file name with no String node and no Set / Get. The names travel in `labels`, an optional input declared after the boxes of before (a found name is marked `~`): a saved workflow and an API prompt are valid as they are.
- WFrame: a pad has a **`fill`**: `colour` (as before) or **`edge`**, the picture's own border pixels carried on outward, row by row and column by column, the corners from the corner pixel. A gradient continues into the border, a blue side stays blue and a red side red; the mask and the feather are the same. The preview shows it.
- WFrame: a new node is born with **no action** (the picture passes through, the line above reads `(no change)`) and the menu on **`crop`**: pick the action and press `+`. It was born with a 1024 × 1024 pad to remove first. A saved workflow keeps its stack.
- WFrame: a **pipette** next to the colour of a pad. It picks the colour from the screen with the browser's eyedropper (the picture up the cable, a node's preview, anything on it; Esc to leave). In a browser with no eyedropper of its own, it picks from the picture in the drawing: click a point of it, the pixel is read from the picture itself, not from the dimmed drawing.
- WSave Image, `from Wnodes on graph`: a WCheckpoint gets the text **`_C_`** and a WLoRA **`_L_`** (they got the node's name).
- **The seven H3 nodes have their own sub-menu, `WextraUI/H3`** (WScene Composer, WSimple Prompt, WScene, WScenes Collection, WLoop Start, WLoop Scene Conditioning, WLoop End); the thirteen utilities stay in `WextraUI`. Only the menu changes: the node types (`h3Scene`, `h3LoopRange`…) are the same, a saved workflow and an API prompt load as they are. The README reads in the same two parts, utilities and H3 scene loop.
- WSave Image: **up to 10 parts** (8 before). The boxes of parts 9 and 10 are declared before `write_batch` and `image_preview`, so a saved workflow and an API prompt are valid as they are; a workflow saved by an older frontend, with values by position only and no names, is read again on load so the two switches get their values back and not part 9.
- WLoRA: a workflow loaded while the **tab was not in front** (or with the node off screen) could come up with the node at a wrong height, the chip picker cut or floating, until something on the node was changed. The height is measured from the node's HTML, and the measure was taken in an animation frame: a page in the background runs none, and the first one it runs can come before the canvas has sized the box, so the text wrapped in a box 0 wide and the measure was garbage. A measure that cannot be taken is now owed, and taken at the first redraw with the box in place; a node resized is measured again, so the chips that wrap do not push the base line out of sight.

## 0.7.1 — 2026-10-07
- WInt🌱 and WFloat: the walk starts from the value you set. The frontend's own callback of a number box snaps every value it gets to a multiple of the step counted from the minimum, and the node sets the step of the arrows to the step of the walk: on WInt🌱 with `step` 2, 1 typed became 2 and the walk went 2, 4, 6 instead of 1, 3, 5 (and a float could be rounded by the settings' precision). The node now rounds by itself (an integer; two decimals) and only clamps: 1, 3, 5. The arrows still move by `step`.
- WSampler / WScheduler: with no tick the `selection` row reads `all · 27`, the length of the list (it read `all`); the count follows a refreshed list.
- Every node: no more **empty pin at the top** of the node above every input while a cable was dragged over the graph (or the mouse passed there). The frontend draws the socket of a widget whenever a cable of its type is in the air, at the place the socket last had; a widget hidden since the node was born (`selection`, `start`, `ops`, `picked`, `rows`, `on_i`, `parts`, the fields of the parts and rows not in use…) has no place, and its socket came up at the top, where a cable could even land. Those sockets are not drawn and take no cable now, on every load too (`wxSlotHidden` / `wxKeepSlotHidden` in `web/wxStyle.js`, used by every node that hides a widget). Under Nodes 2.0 a hidden widget is no longer a row of its own either.
- WSave Image: with **image preview** off, the thumbnails could still appear in the node: a workflow loaded from the queue / history panel brings the outputs to the node by a road that skips the node's own hook, and the frontend hung the thumbnails from its drawing of the node. That drawing is not run while the switch is off, and whatever it hung before is taken down.
- WSave Image, `from Wnodes on graph`: the nodes found are listed **by type**, the type above its group; every ticked row has the handle `≡` of the selection of WSampler / WScheduler, drag it to set its place in the name. The text of a part made here is now a short tag where there is one: `_sa_` for a WSampler, `_sc_` for a WScheduler, `_S_` for a WInt🌱 / WFloat that feeds a `seed` (or `noise_seed`), `_st_` for one that feeds `steps`, `_cfg_` for one that feeds a `cfg` (the node follows the cable, through Reroute and Set / Get); the tag is shown on the row, small, before the id. Other nodes keep their name as text.
- WFrame: the rows of the stack move by **drag**, with the handle `≡` of the other nodes (the `↑` `↓` buttons are gone). The **arrow keys** move the open rectangle by 1 px of its picture, 10 with Shift (click the drawing first). A **`mask`** button top right shows the pad mask as the run makes it: black all around, the picture where it comes out, fuchsia where the pads add pixels, the feather fading in. The number boxes of the settings **slide** (press and drag sideways, 10 per px with Shift). Above the stack, a line with what the node does, as it goes in a WSave Image name; the line of steps under the drawing is gone. The outputs **`width`, `height` and `info` are gone**: what was done goes in the name with no cable (below), and is **shorter**: one letter per action, the pad border folded when the sides match, no final size: `c800x1000_p100x0` (it read `crop800x1000_pad100-0-100-0_1000x1000`); `-40x0` is a cut, `r1024x683` a resize.
- WSave Image: `from Wnodes on graph` lists **WFrame** too, text `_fr_`, value `{#id}` = what the node did in its last run while the stack is the one it ran with, else the numbers of the stack.
- WInt🌱: **`increment-wrap`** in its control, like the menus: the wheel from the value you set to `until`, round to the start at the end, **with no `carry` cable**; `until` is live as soon as the control is on it. The label reads `+1/run · 1 → 4 ↻`. With a cable the wheel is the one of before.
- WSave Image: the parts move **on the node**: every bar has the handle `≡` on its left; drag it and drop the part on another one, it takes that place (the one under the pointer lights up), the parts between move up or down; values and cables follow, as with `−` and `+`. While the drag lasts the sockets of the widgets stay down: they came up as the pointer passed at their height, an invitation to cable in the middle of a move.
- WSave Image: `{#id}` inside a **subgraph** looks for node `id` in the subgraph of the saving node first (the run names a node there `7:12`, the graph says 12): the name told the value of a root node with that number, or nothing. On `int`, a value that is not a number (a name) goes in the preview as it is, like in the file (it read `NaN`).

## 0.7.0 — 2026-10-03
- WFrame is now a **stack of actions**: crop, pad and resize, in the order you put them, as many as the job needs (up to 8), instead of one fixed crop → resize → place. A menu and `+` / `−` / `↑` / `↓` under the node; click a row to open its settings. Each action sees the picture as the ones before it left it: crop a detail, then pad it to `1:1` (the pad's aspect makes the smallest square canvas around it); or resize, then pad for the outpaint. A crop has width × height (0 = the whole side) or an aspect, an anchor and a shift; a pad has the canvas size (0 = keep that side) or an aspect, an anchor, a shift, its colour and feather, and the four borders typed by hand (− = cut); a resize has `width` / `height` / `long side` / `short side` / `scale %` / `fit in box` / `cover box`. The pad mask sums over the pads and follows the crops and resizes after them. One `method` for every resize.
- WFrame: a **preview under the stack**. The final frame in red, every crop and pad a rectangle in the colour of its row, the border a pad adds filled with its colour and measured on each side, what is cropped, cut or covered outside and dimmed, the feather as a fading band, the steps of the run in one line. Click a rectangle to open its action, drag it to move it, pull a corner or a side to size it (a locked aspect holds), double-click puts its shift back to 0; a button top right zooms on the open action, again for the whole. The picture is the node's true input (the run sends a small copy to the temp folder); before the first run it is read from the Load Image up the cable. The drawing follows the same rules as the node, with the same rounding.
- WFrame: a workflow saved with the WFrame of 0.6 loads as a stack (its crop, its resize, then a pad of the new size with its anchor, offsets, colour and feather) and runs the same. The widgets `new_width`, `new_height`, `crop_to`, `crop_width`, `crop_height`, `crop_anchor`, `resize_to`, `resize_value`, `pad_anchor`, `offset_x`, `offset_y`, `pad_color` and `feathering` are gone: an API prompt takes `ops` (the stack as JSON, see the node's `?`) and `method`. The cut on a side where the picture was bigger than the new size used to follow `pad_anchor` even with a `crop_anchor` set; a pad now has one anchor, and it rules both the border and the cut.
- WSwitch: a saved workflow could come back with the cables of its first slot slid by one position (a `clip` where the `model` was, and so on down the slot), every time the graph was loaded; the file on disk was right. The frontend ties a cable to the position of its socket, and the node put its sockets in order without taking the cables along. The sockets now move with their cables (`web/wxSlots.js`), and the sockets of a saved workflow are put in place before its cables arrive. Also, the `carry` input of WSwitch, promised in 0.6.0, was taken away by the node itself as soon as it was born: it is there now, under the slots.

- WDifference: `add` and `remove` sit right under `track`, the box they act on; the empty boxes say what goes in them (`track changes of these nodes: 74, 12`, `ignore (74.seed, 12)`).
- WSave Image: the W of `from Wnodes on graph` is red, as in the wordmark.

Fixed on the way: the hover tooltip of the frontend was not switched off over a WextraUI node (two `setup` in one extension, the second replaced the first).
- WSwitch: **20 slots** (was 10). A saved workflow loads as it is: the slots it did not have are off. And WSwitch **walks**: new `control` (`fixed` / `increment` / `decrement` / `randomize`, at the end, ignored by the backend) moves the slot that is on over the slots in use after every queued run, coming round at the ends; new **`carry`** input and output (the output is last), so a switch can be driven by the odometer cable or drive the next node, like the other nodes that walk. In WSave Image `{#id}` of a WSwitch is the slot that is on, counted from 0.
- **WRouteIndex is now WRoute Index** (display name only): **up to 20 outputs** (was 4), counted from 0, shown as you use them — connect the last one and another appears, like the slots of WSwitch, whose `index` fits as it is. A saved workflow keeps its outputs; `index` above 3 was refused before, now it reaches 19.
- WScenes Collection H3: the sockets grow by themselves, like the slots of WSwitch — one empty socket after the last scene, up to 20; **unplug a scene in the middle and the ones after it move up**; the **`+`** chip after a scene's label opens an empty socket right below it, to slip a scene in between. The `+ Add scene` / `− Remove last scene` buttons are gone. The labels count as the loop does (`0 · scene` is scene 0).
- Renamed: **WLoad Lora & Trigger is now WLoRA**. Display name only: the class name does not change, a saved workflow loads as it is, an API prompt is the same. (WCheckpoint and WInt🌱, new in this version, are born with these names.)
- WDifference: new box **`track`**, above `ignore` (a workflow saved by 0.5.x with text in `ignore` is put back in place at load): empty = every node is tracked, as before; with ids in it (`74, 12`, or a single widget `74.seed`) only these are compared. Two buttons under it, **`add`** and **`remove`** — select the nodes on the canvas and press: their ids go into `track` (no doubles), or out of it with their `74.seed` entries. The label counts the selection (`add · 3`, `remove · 2`). The buttons take no slot in the workflow file. `ignore` stays for the exceptions inside what is tracked, and both accept the id of a node inside a subgraph (`12:5`).
- New node **WCheckpoint**: the core Load Checkpoint with the `folder` menu above the name and the seed-style control after generate under it, like WLoRA — `increment` / `decrement` / `randomize` walk the checkpoints of the folder chosen across queued runs, the label shows where you are (`folder · 3/12` = runs to queue). Same load as the core node (`MODEL`, `CLIP`, `VAE`), plus `name` as a string for WSave Image. Title = checkpoint name once collapsed. `folder` is an optional input (in `object_info`), an API prompt without it is valid, a folder that is gone never stops a run.
- New nodes **WSampler** and **WScheduler**: the `sampler_name` and `scheduler` menus as nodes of their own, with a `selection` drop-down above the name and the seed-style control after generate under it. `selection` reads `all`; open it, tick the names you want, drag them into order, close it and it reads `custom · n`: from then on those names, in that order, are the menu of the name — the arrows, the list and the walk of `increment` / `decrement` / `randomize` only meet them (saved in the workflow). Cable them into the KSampler's `sampler_name` / `scheduler` turned into inputs; queue several runs with `increment` and each one takes the next name. The name also comes out as a string for WSave Image. Title = the name once collapsed.
- **`carry`, the odometer cable**, on every node that walks: WSampler, WScheduler, WCheckpoint, WLoRA and WFloat have a `carry` input and a `carry` output (last, after the outputs of before). Cable the output of the fast node, on `increment-wrap`, into the input of the slow one: each time the fast one comes back from the last name to the first, the slow one moves one step of its own (forward; back with `decrement`; a random one with `randomize`; a driven node no longer moves by itself, its control reads `on carry`). Chain them — scheduler → sampler → checkpoint — and the label of the input counts the runs of the grid (`carry · 3 × 4 = 12 runs`). The cable may pass through Set / Get (KJNodes) and Reroute. The cable is a type of its own that passes a string: the backend, comfy-cli and an agent see an ordinary optional link, an API prompt without it is valid; the beats happen in the interface. `tools/migrate_outputs.py` gives a WLoRA saved by 0.4.x its fifth output.
- New node **WInt🌱**: WFloat on an integer, `step` 1 by default and `randomize` too — a seed that walks after every queued run, for the KSampler's `seed` turned into an input or any INT.
- WFloat and WInt🌱 take the `carry` cable both ways and get **`until`** back, as the arrival of a wheel: with a cable in or out the number goes from the value you set (the start, kept in a hidden `start` box) to `until` by `step`, comes round and beats the next node. Without a cable `until` does nothing (it is greyed out) and the walk is as free as before: `decrement` past `until` is not stopped. Both new inputs are optional, at the end: a saved WFloat and an API prompt of before are valid as they are.
- WLoRA: with a folder chosen, `increment` / `decrement` / `randomize` did not move — the folder was handed to the control's filter as a bare pattern, and the frontend takes a bare string as text (a regex must be wrapped as `/abc/`, its own convention), so every LoRA was filtered out. Now wrapped: the walk keeps to the folder. With `(all)` it already moved.
- The `folder` menu, the filter box of the control and the title that follows the name are now one shared piece (`web/wxFolder.js`, `src/wxFolders.py`) used by both loaders; WLoRA behaves as before.
- `pyproject.toml` description brought up to date (it still named WRoute, WDifference and the H3 loop as the whole pack).

For a strength that walks, cable a **WFloat** on `strength_model` (and on `strength_clip`, if it should walk too): it moves by its `step` after every queued run, no arrival, no floor. An old API prompt that still sends any of the removed inputs is accepted and ignored; a saved workflow that had a walk or `lora scope` = `folder` loses it, and `tools/migrate_outputs.py` says so.
- WLoad Lora & Trigger: new `folder` menu above the LoRA name — the folders of your LoRA list at every depth (`(all)`, `Krea2`, `Krea2 / Characters`, `Krea2 / Characters / Heroes`, ...); it replaces `lora scope`. Its label shows where you are in the folder (`folder · 3/12`, with `(all)` in the whole list: `folder · 3/240`): that is how many runs to queue. It lives in the node: `lora_name` stays a full path, an API prompt without `folder` is still valid, a folder that is gone never stops a run. Workflows saved before open with `(all)`.
- WLoad Lora & Trigger: the pack makes no network call any more — the `civitai` switch is now `rgthree_info`, and the official trigger words are read from the `<lora>.rgthree-info.json` that rgthree-comfy saves next to the LoRA, not looked up online; off (and greyed out) when that file is not there. Outputs down to four (`MODEL`, `CLIP`, `prompt`, `name` — `name` moves from position 6 to 3); `trigger_words`, `civitai_list`, `tags_list`, `info` are gone. A new `base:` line under the chips shows what the header and the rgthree file say. A saved workflow with the old `civitai` switch carries its value over to `rgthree_info` by itself; cables on the outputs that were dropped are lost.
