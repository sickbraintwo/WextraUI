# Changelog

## 0.6.0 — 2026-09-24
- WSave Image: **`{#id}`** in any text (a part's value, `subject`, `folder`) = the value that WextraUI node used in this run, read from the run's prompt: the sampler's name for WSampler, the scheduler for WScheduler, the bare file name for WCheckpoint / WLoRA, the number for WFloat / WInt🌱, the slot that is on (from 0) for WSwitch — no cable, and the name always tells what the run used; a node not in the run gives nothing. The preview resolves it from the graph as the nodes walk. New button **`from Wnodes on graph`**: the WextraUI nodes of the workflow by name (the type's name, or the title you gave; alphabetical, so a type's nodes sit together) with their value of now; the ones that walk or move on a carry cable are ticked, in the order of the carry chain, slow to fast, drag to change it; `add` makes one part for each (text = the node's name, value `{#id}` locked so a slip cannot lose the node, `−` removes it). Defaults: `write_batch` off, `digits` 2. `+ Add part` reads `+`.
- WScene Composer H3: the button that folds and unfolds the text areas is a chevron, `⌃` / `⌄`.
- WDifference: `add` and `remove` sit right under `track`, the box they act on; the empty boxes say what goes in them (`track changes of these nodes: 74, 12`, `ignore (74.seed, 12)`).
- WSave Image: the W of `from Wnodes on graph` is red, as in the wordmark.
- README and the 20 help pages speak with one voice: the README opens with why the pack exists (time works for you) and the carry picture; the help pages keep every fact and gain headings and shorter sentences. The `?` pages ship in `web/docs/`.
- **Nodes 2.0** (`Comfy.VueNodes.Enabled`): the pack works there too. What a node paints on the canvas has no place in that renderer, so the on/off pills of WSwitch, the `+` chips of WScenes Collection H3 and the on/off · − · + bar of WPrompt Rows get an HTML twin in the node's DOM; the buttons and the part bars of WSave Image, `add` / `remove` of WDifference and the `?` were already there. A widget hidden or shown after the node came in (a row, a part) is re-read, and the value watches of WLoRA, WCheckpoint and WFrame run on a timer (Nodes 2.0 never redraws a node on the canvas). Switching Nodes 2.0 off puts the classic size back on every WextraUI node (Nodes 2.0 measures taller rows and writes that height into the node). Fixed on the way: the hover tooltip of the frontend was not switched off over a WextraUI node (two `setup` in one extension, the second replaced the first).
- WSwitch: **20 slots** (was 10). A saved workflow loads as it is: the slots it did not have are off. And WSwitch **walks**: new `control` (`fixed` / `increment` / `decrement` / `randomize`, at the end, ignored by the backend) moves the slot that is on over the slots in use after every queued run, coming round at the ends; new **`carry`** input and output (the output is last), so a switch can be driven by the odometer cable or drive the next node, like the other nodes that walk. In WSave Image `{#id}` of a WSwitch is the slot that is on, counted from 0.
- **WRouteIndex is now WRoute Index** (display name only): **up to 20 outputs** (was 4), counted from 0, shown as you use them — connect the last one and another appears, like the slots of WSwitch, whose `index` fits as it is. A saved workflow keeps its outputs; `index` above 3 was refused before, now it reaches 19.
- WScenes Collection H3: the sockets grow by themselves, like the slots of WSwitch — one empty socket after the last scene, up to 20; **unplug a scene in the middle and the ones after it move up**; the **`+`** chip after a scene's label opens an empty socket right below it, to slip a scene in between. The `+ Add scene` / `− Remove last scene` buttons are gone. The labels count as the loop does (`0 · scene` is scene 0).
- Renamed: **WLoad Lora & Trigger is now WLoRA**. Display name only: the class name does not change, a saved workflow loads as it is, an API prompt is the same. (WCheckpoint and WInt🌱, new in this version, are born with these names.)
- WDifference: new box **`track`**, above `ignore` (a workflow saved by 0.5.x with text in `ignore` is put back in place at load): empty = every node is tracked, as before; with ids in it (`74, 12`, or a single widget `74.seed`) only these are compared. Two buttons under it, **`add`** and **`remove`** — select the nodes on the canvas and press: their ids go into `track` (no doubles), or out of it with their `74.seed` entries. The label counts the selection (`add · 3`, `remove · 2`). The buttons take no slot in the workflow file. `ignore` stays for the exceptions inside what is tracked, and both accept the id of a node inside a subgraph (`12:5`).
- New node **WCheckpoint**: the core Load Checkpoint with the `folder` menu above the name and the seed-style control after generate under it, like WLoRA — `increment` / `decrement` / `randomize` walk the checkpoints of the folder chosen across queued runs, the label shows where you are (`folder · 3/12` = runs to queue). Same load as the core node (`MODEL`, `CLIP`, `VAE`), plus `name` as a string for WSave Image. Title = checkpoint name once collapsed. `folder` is an optional input (in `object_info`), an API prompt without it is valid, a folder that is gone never stops a run.
- New nodes **WSampler** and **WScheduler**: the `sampler_name` and `scheduler` menus as nodes of their own, with a `selection` drop-down above the name and the seed-style control after generate under it. `selection` reads `all`; open it, tick the names you want, drag them into order, close it and it reads `custom · n`: from then on those names, in that order, are the menu of the name — the arrows, the list and the walk of `increment` / `decrement` / `randomize` only meet them (saved in the workflow). Cable them into the KSampler's `sampler_name` / `scheduler` turned into inputs; queue several runs with `increment` and each one takes the next name. The name also comes out as a string for WSave Image. Title = the name once collapsed.
- **`carry`, the odometer cable**, on every node that walks: WSampler, WScheduler, WCheckpoint, WLoRA and WFloat have a `carry` input and a `carry` output (last, after the outputs of before). Cable the output of the fast node, on `increment-wrap`, into the input of the slow one: each time the fast one comes back from the last name to the first, the slow one moves one step of its own (forward; back with `decrement`; a random one with `randomize`; a driven node no longer moves by itself, its control reads `on carry`). Chain them — scheduler → sampler → checkpoint — and the label of the input counts the runs of the grid (`carry · 3 × 4 = 12 runs`). The cable may pass through Set / Get (KJNodes) and Reroute. The cable is a type of its own that passes a string: the backend, comfy-cli and an agent see an ordinary optional link, an API prompt without it is valid; the beats happen in the interface. `tools/migrate_outputs.py` gives a WLoRA saved by 0.4.x its fifth output.
- New node **WInt🌱**: WFloat on an integer, `step` 1 by default and `randomize` too — a seed that walks after every queued run, for the KSampler's `seed` turned into an input or any INT.
- WFloat and WInt🌱 take the `carry` cable both ways and get **`until`** back, as the arrival of a wheel: with a cable in or out the number goes from the value you set (the start, kept in a hidden `start` box) to `until` by `step`, comes round and beats the next node. Without a cable `until` does nothing (it is greyed out) and the walk is as free as before: `decrement` past `until` is not stopped. Both new inputs are optional, at the end: a saved WFloat and an API prompt of before are valid as they are.
- WLoRA: with a folder chosen, `increment` / `decrement` / `randomize` did not move — the folder was handed to the control's filter as a bare pattern, and the frontend takes a bare string as text (a regex must be wrapped as `/abc/`, its own convention), so every LoRA was filtered out. Now wrapped: the walk keeps to the folder. With `(all)` it already moved.
- The `folder` menu, the filter box of the control and the title that follows the name are now one shared piece (`web/wxFolder.js`, `src/wxFolders.py`) used by both loaders; WLoRA behaves as before.
- `pyproject.toml` description brought up to date (it still named WRoute, WDifference and the H3 loop as the whole pack).

## 0.5.0 — 2026-09-21
- WLoad Lora & Trigger: with a few words picked the chip box was cut at the bottom and the `base:` line went out of sight; the box now grows with the picked words (the lists still scroll).
- WSwitch has its `?` help page; README pictures redone for WSave Image, WLoad Lora & Trigger, WFloat and the opening one, new one for WSwitch.
- WSave Image: any part can be removed or added in the middle, like the rows of WPrompt Rows — above each part there is a slim bar (`part 1`, `part 2`, ...) with two chips: `−` removes that part (the parts after it move up), `+` opens an empty part right below (the parts after it move down); values and cables follow. `+ Add part` shows only while there are no parts; `− Remove last part` is gone.
- WFrame: `new_width`, `new_height`, `crop_width`, `crop_height` take any value, to the pixel. They had a step of 8 and the frontend snaps a typed number to the step: the new size went to multiples of 8, and the crop (minimum 1) to 8k+1 — 512 typed became 513.
- New node **WSwitch**: a switch with slots of `inputs_per_slot` cables (any type), one on/off pill per slot, only one on; the slot that is on goes out position by position, the branches behind the other slots do not run (lazy inputs); the type of each position is learned from the first cable and set on every slot and on the output; slots grow as you connect (2 to 10). The first output, `index`, is the slot that is on, counted from 0.
- WFloat: `until` is gone. `control` (`fixed` / `increment` / `decrement`) now works like the seed — after every queued run `value` moves by `step` in that direction, with no arrival and no floor (negative values are legitimate); the label shows the step and its direction (`+0.1/run` / `−0.1/run`). `value`'s range is now −100 to 100. An old API prompt that still sends `until` is accepted and ignored.
- WLoad Lora & Trigger is shorter: `strength_control`, `strength_step` (and `strength_until` before them) and `lora scope` are gone. For a strength that walks, cable a **WFloat** on `strength_model` (and on `strength_clip`, if it should walk too): it moves by its `step` after every queued run, no arrival, no floor. An old API prompt that still sends any of the removed inputs is accepted and ignored; a saved workflow that had a walk or `lora scope` = `folder` loses it, and `tools/migrate_outputs.py` says so.
- WLoad Lora & Trigger: new `folder` menu above the LoRA name — the folders of your LoRA list at every depth (`(all)`, `Krea2`, `Krea2 / Characters`, `Krea2 / Characters / Heroes`, ...); it replaces `lora scope`. It narrows the LoRA menu and the walk of `increment` / `decrement` / `randomize` to that folder and what is under it; pick a folder and the LoRA moves to the first one inside. Its label shows where you are in the folder (`folder · 3/12`, with `(all)` in the whole list: `folder · 3/240`): that is how many runs to queue. It lives in the node: `lora_name` stays a full path, an API prompt without `folder` is still valid, a folder that is gone never stops a run. Workflows saved before open with `(all)`.
- WLoad Lora & Trigger: the pack makes no network call any more — the `civitai` switch is now `rgthree_info`, and the official trigger words are read from the `<lora>.rgthree-info.json` that rgthree-comfy saves next to the LoRA, not looked up online; off (and greyed out) when that file is not there. Outputs down to four (`MODEL`, `CLIP`, `prompt`, `name` — `name` moves from position 6 to 3); `trigger_words`, `civitai_list`, `tags_list`, `info` are gone. A new `base:` line under the chips shows what the header and the rgthree file say. A saved workflow with the old `civitai` switch carries its value over to `rgthree_info` by itself; cables on the outputs that were dropped are lost.

## 0.3.6 — 2026-09-15
- **Saved workflows read right by position.** The boxes the scripts draw (WLoad Lora & Trigger: `lora scope`, `strength control` / `step` / `until`) are now inputs of the node, same place, same order, optional with a default: `object_info` lists them and the saved `widgets_values` match it one to one, so comfy-cli's UI-to-API translator and MCP `list_workflow_slots` pair every value with the right input (before: 40 slots flagged `pairing_suspect` on 20 loaders in one workflow). The backend ignores them: the walks stay in the node.
- Buttons, pickers and tables (WSave Image `+`/`−`, WScene Composer H3 table and toggle, WFrame color pad, WScenes Collection H3 buttons, the loader's chip picker) take no slot in `widgets_values` any more (`wxCompactWidgets` in `web/wxStyle.js`); a workflow saved with the old holes loads unchanged. `tools/migrate_outputs.py` (stage 0.3.6) cleans the files on disk.
- **`tools/migrate_outputs.py` rewritten, safe to run twice.** The previous version trusted a version marker and remapped the outputs of every WSave Image / WDifference / WScene Composer H3 / WLoop Start H3 it met, so a workflow saved with the current nodes (no marker yet) got its output slots and links scrambled. Now every node is judged as saved: old layout (by output names, or by a link whose target fits the old slot) is remapped, a current one is left alone, a scrambled one without links is rebuilt, and the loader's older widget layouts (7/8/9 values) are expanded to today's 12.
- **Old files load right, not just safe.** A node reads the frontend's `widgets_values_named` (saved next to `widgets_values` since frontend 1.5x) when it loads: a value goes to the box that had it by name, whatever slot it sat in, so a workflow saved by an older WextraUI opens with its own strengths and settings instead of defaults. WLoad Lora & Trigger also puts a strength that had slid into the control-after-generate slot back where it belongs; WSave Image's two switches fall back to their defaults when an old file left them empty. `migrate_outputs.py` does the same on the file, and drops the copy of `pad_color` / `beats_json` that the WFrame color pad and the WScene Composer H3 table used to save.
- **Registry lint.** `comfy node validate` flagged ten `E702` (two statements on one line) that the registry says will soon be refused: gone, the check passes clean.
- **`tools/selftest.py`** — the pre-push check from outside the UI: registry lint, object_info, every workflow given migrated on a copy and paired by position (or by comfy-cli when importable) with every value type-checked, and one small `/prompt` run per node family. `python tools/selftest.py --comfy <comfy.exe> my.json` — exit 1 on any problem.
- Nothing changes in the node's look or in the API you already call.

## 0.3.5 — 2026-09-15
- **WDifference**: a workflow saved before `changes_max` existed loaded with the shifted value (`ignore`'s empty text) in that box, shown as 0, and the run was refused ("couldn't be converted to INT"); a load-time guard in `web/wxRunDiff.js` now resets an invalid `changes_max` to 240.
- **WSave Image**: the saved files are always declared in `/history` as `images` (`filename`, `subfolder`, `type`), like the standard Save Image, whatever the **image preview** switch says; the switch now only decides the thumbnails inside the node. Scripts and agents can fetch the exact file through `/view` instead of guessing the counter.
- **WDifference**: `changes_max` and `ignore` are optional inputs (same place, same order): API exports made before they existed run again. The diary of the run also goes into the PNG metadata (`WDifference` chunk: `key`, `tag`, `changes`, readable lines) of every image saved downstream, so the file name can stay short.

## 0.3.4 — 2026-09-14
- New: **WPrompt Rows** — the prompt as rows: on/off chip per row (it also switches a linked external string), auto-growing text areas, + / − to add and remove rows, `join` = comma / space / newline / none.
- New: **WSimple Prompt H3** — the H3 prompt without time-codes: scene, action in order, camera, sound, what stays fixed, what moves, final state, three `avoid` fields. One `prompt` output.
- **WSave Image**: `images` is optional — unplugged, the node only composes the name (`prefix` / `name`). The `preview` now follows linked fields (`folder`, `subject`, parts) reading the upstream widget value, or shows `{subject}` / `{int}` placeholders, and refreshes on its own (it no longer depends on the widget callback, which the frontend skips for single-line text and Nodes 2.0). **New first output `images`** (the input batch passed through) — `prefix` / `name` move to slots 2 and 3: rewire, or run `tools/migrate_outputs.py` on your workflows. **write batch** switch (on by default) appends `_B{batch}{index}`: images in the run and the number of this one (`_B41`, `_B42`…); the same placeholders work in any text field. **image preview** switch (off by default): thumbnails inside the node after the run. Long names no longer fail the save: the name is cut so the full path fits Windows (259), the counter keeps files apart.
- **WLoad Lora & Trigger**: `control after generate` under the LoRA name (fixed / increment / decrement / randomize / increment-wrap) and a `lora scope` menu (any / folder = the folder of the current LoRA), with the position in the list on the label (3/12). Strength walk: `strength control` / `step` / `until` under `strength_model` move it one step per queued run (0.4 -> 1.0 in seven runs), `strength_clip` untouched: queue N runs, each takes the next LoRA. Saved workflows: run `tools/migrate_outputs.py` (it slips the control value into place) or the strengths shift by one.
- **WDifference**: `changes` is now short and file-name safe — `<node id>.<widget>→<new value>` (`74.seed→6_12.strength→0.6+Upscale`), no titles, no old value, widget cut at its first `_`, no spaces or forbidden characters — so it can go straight into the file name; the `.log` keeps the readable text. New `ignore` field: node ids (`74, 12`) or single widgets (`74.seed`) left out of every output. `changes_max` (default 240) caps the string with `+N`. Model / LoRA files show by bare name, no folder, no `.safetensors`.
